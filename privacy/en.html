Privacy Policy

Effective and last updated: November 1, 2026 · Extension version: 1.7.0 (v1.6 has local favorites only)

This policy explains how Agent Leaderboard handles data when you use its Chrome search assistant and website.

Searches and filters run on your device. Anonymous favorites stay local; cloud favorites are optional. In v1.7, you can sign in separately in the extension and website with the same GitHub account to share account favorites. Choosing sign-in sends favorite repository identifiers and public metadata to Cloudflare Workers and D1. Search terms and selected text are not uploaded. No account is needed for searches or local favorites. The extension does not read browsing history, cookies or full webpage content and contains no advertising or analytics code. Catalog updates make necessary network requests.

Scope

This policy covers the Agent Leaderboard Chrome extension and agentskills.media, maintained by Jiancheng Pan (GitHub: jaychempan). The extension searches, filters and bookmarks public AI tool repositories, and copies repository links and installation prompts.

The extension and website use separate local storage and login sessions. When you sign in separately in v1.7 and on the website, the same GitHub account shares favorites through one Cloudflare Worker and D1 database. Without sign-in, each client’s local favorites remain separate. GitHub repositories, external websites and AI coding services you choose to open are governed by their own privacy policies.

What the extension handles locally

Search terms, filters and text you select
Terms entered in the extension or address bar, and text you actively submit through the selection context menu, are used only to search the local catalog. The extension does not automatically scan webpages. Current searches and filters are kept in browser session storage; context-menu requests are removed after receipt and are not sent to a search server. Address-bar searches and fallback search pages may include terms in a local chrome-extension:// page URL.
Bookmarked repositories
Without sign-in, repository identifiers and public snapshots are stored locally. First sign-in merges existing local favorites into the current account using stable repository IDs and import receipts to avoid duplicates. It does not import a previous account’s cloud list into another account. Older favorites without a resolvable repository ID remain local with a pending-import count. Account favorites and snapshots for repositories that leave the catalog stay in D1. The extension caches account favorites only for the current browser session, without a persistent account mirror. Local import-deduplication records may retain original local favorite snapshots, the assigned account, and batch import/cleanup receipts after sign-out to resume imports and prevent duplicates or account mixing.
Optional extension account session
GitHub sign-in starts only when you choose it in Favorites, using Chrome’s authentication window. The extension keeps PKCE verification data, an up to eight-hour site session token, and its current account cache only in chrome.storage.session. It does not persist account tokens, GitHub tokens, or an account-favorites mirror in local storage. Browser restarts and extension reloads, disabling, or updates clear this session storage and may require signing in again. Closing one side panel does not necessarily clear it. The Worker reads your identity using the GitHub access token, then discards it without sending it to the extension. No Google account or repository access permission is required.
Preferences and catalog cache
Language, theme, public catalog and trend caches, and the last check time are stored locally to restore preferences, support offline searches and trend viewing, and control update frequency.
Copied links and installation prompts
Only when you click a copy button does the extension write a repository link or generated installation prompt to your system clipboard. It does not read the clipboard, automatically send content to an AI service, or run installations. If you paste content into another application, that application handles the content you choose to share.

Network requests and third-party services

Public catalog and trend updates

On first opening, when opened more than 24 hours after the last successful check, or when you manually refresh, the extension requests https://agentskills.media/data/discovery_index.json and https://agentskills.media/data/trends.json over HTTPS. This request does not include search terms, favorites, selected text or browser cookies. Cached or bundled catalog and trend snapshots remain usable offline.

As with other website requests, hosting and network infrastructure serving the website receive connection information such as your IP address, request time, request path and browser request headers. They may retain access logs for service delivery, security or troubleshooting. The static website is published through GitHub Pages, DNS is managed by Tencent Cloud, and the separate account and favorites API runs on Cloudflare Workers. Infrastructure providers handle data under their own policies, including the GitHub Privacy Statement. This project does not set or promise a uniform retention period for those infrastructure logs.

Sign-in and cloud favorites you choose to enable

After you choose sign-in in v1.7, the extension uses https://agent-leaderboard-api.jaychempan.workers.dev to start GitHub authorization, exchange a short-lived, single-use PKCE-bound code for a site session, and read account favorites. Adding or removing favorites sends repository IDs, public repository snapshots, and the current site session to this API. First import also sends deduplication identifiers. To import older favorites without IDs, the extension sends saved public repository names to the Worker, which queries GitHub’s public repository API to resolve names and IDs. This retrieves public metadata without requesting extra repository permissions or accessing private code. Searches, filters, selected text, and webpage content are not sent to the favorites API. Ordinary sign-in obtains your GitHub identifier, username, and public avatar without requesting repository-code, Gist, or email access. Site sessions and GitHub tokens are not placed in URLs. The Worker uses a short-lived HttpOnly cookie during login redirects; the extension does not read cookies.

Signed-in website and extension changes save through the online API. Failures roll back and show a retry message; offline writes are not queued. Sync reads changes successfully saved on other devices. D1 cloud favorites are not deleted when a tab closes, the extension signs out or is uninstalled, or a session expires.

Links you choose to open

Opening a repository, README, website or feedback link makes a normal browser request to the destination, which receives request information under its own policies. The extension does not read conversations in ChatGPT, other AI tools or other browser extensions.

Why the extension uses its permissions

storage
Stores local catalog and trend caches, anonymous favorites, language and theme preferences, plus temporary search, login-verification, and account-session caches.
sidePanel
Displays the search assistant in Chrome’s side panel.
contextMenus
Provides a menu to search selected text. Selected text is used only when you actively click that menu item.
identity
Uses launchWebAuthFlow to open GitHub sign-in when you choose it and receive the result. It does not sign in with Google or read Google account data.
https://agent-leaderboard-api.jaychempan.workers.dev/*
Allows optional login exchange, first import, and the current account’s favorite reads, additions, removals, and sign-out. Extension connect-src is limited to the catalog and API origins; no remote executable code is loaded.
https://agentskills.media/*
Allows public catalog and trend updates from the official website. The extension does not request permissions to read browsing history, cookies, arbitrary webpage content or clipboard contents.

Website data

The website stores language, theme, list-view preferences and website favorites in browser localStorage. Search and filtering run in your browser and are not sent to the favorites database. Without sign-in, favorites stay on the current device.

Optional GitHub sign-in and cloud favorites

When the cloud service is configured, you can choose to sign in with GitHub. The Worker obtains your GitHub user identifier, username and public avatar/profile URLs to identify the account; ordinary sign-in does not request repository, Gist or email-reading permissions. The Worker uses the GitHub access token only to read your identity, then discards it without sending it to the website frontend. A short-lived, single-use code bound to a browser-generated verifier exchanges the login result for a site session; GitHub tokens and site session tokens are never placed in URLs. The browser keeps the site session in the current tab’s sessionStorage for up to eight hours. Refreshing can restore sign-in; closing the tab or session expiry may require signing in again. API requests use the site session token without relying on third-party cookies. During login redirects, the Worker uses a short-lived HttpOnly cookie to validate the flow. Existing local favorites are merged on first sign-in, and signed-in additions and removals save to the current account through the online API. Failed requests restore the previous state and show a retry message; offline changes are not queued for background upload. Website favorites do not automatically change GitHub Stars or require reading or changing your repository code.

Cloudflare D1 stores account identifiers and public account details, hashes of site session tokens, short-lived authorization checks, local-import deduplication identifiers, repository identifiers, public repository snapshots and timestamps. The Worker uses the current session to restrict users to their own favorites; signed-in favorites remain only in the current page’s memory and require a network request when the page reopens. Browser localStorage retains anonymous favorites, legacy backups and first-import records, without an account-favorites mirror or login token. Short-lived session and login-verification data are kept only in sessionStorage. This is not end-to-end encrypted storage: maintainers can manage cloud records for service operation, troubleshooting and deletion requests. Cloudflare and GitHub receive connection information needed for sign-in and requests, under the Cloudflare Privacy Policy and the GitHub Privacy Statement linked above. Signing out revokes the current session; clearing local data does not delete saved cloud favorites.

The website leaderboard displays daily page views (PV) and total visitors (UV); the extension does not include this counter. Loading the leaderboard at https://agentskills.media or https://jaychempan.github.io/Agent-Leaderboard/ sends one request to the public soxft/busuanzi service at https://busuanzi.9420.ltd/api. Both hosts share one canonical namespace. A virtual path containing the Asia/Shanghai date groups daily page loads; total visitors are deduplicated by the service, not verified real people. Board, filter and language changes do not recount. The service identifies visitors using IP, browser User-Agent and a signed anonymous identity. That identity is stored in localStorage as st_visit_identity_v1 and sent with statistics requests. Clearing storage or switching devices can affect deduplication.

Visit-counter requests contain only the canonical site address, statistics date and anonymous identity, with an origin-only Referer. They do not send searches, query strings, favorites, referring-page URLs or third-party cookies. The service receives normal connection information including IP and browser headers; its open-source implementation hashes statistics identifiers. The public service has no SLA or data-integrity guarantee, and this project does not promise its retention period. History from previous services has not been migrated. Local preview requests only the local /api/visits endpoint, storing daily counts and anonymous browser IDs in its local database. Local IDs are stored as st_local_visit_id, never sent to third parties; the local counter does not record IP addresses. Other preview hosts do not enable statistics.

This privacy page does not load visit counters, external fonts or third-party scripts. Loading the page itself still makes the hosting requests described above. The website’s example installation-prompt button only writes the content you choose to copy; it does not automatically contact AI services.

Retention, controls and deletion

  • Extension favorites: Without sign-in, click a bookmark again to remove the local favorite. While signed in, removal deletes the current account’s D1 favorite through the API. Other devices and the website see the change after syncing. Failures roll back, without queued offline deletion. Unresolved older favorites that have not imported must still be managed locally.
  • Temporary searches: Clearing a search or changing filters updates the current session state. Closing one side panel does not necessarily clear session storage. The browser clears extension session storage when the browser restarts or the extension is reloaded, disabled or updated.
  • Extension sign-out and uninstall: Signing out revokes the current extension session and clears its account cache. It does not sign out the separate website session or delete cloud favorites. Uninstalling removes local favorites, settings, catalog caches, and short-lived sessions. Local favorites that have not successfully imported will be lost; saved cloud favorites can be restored by signing in again. Browser history, tab URLs, system clipboard contents and content copied into other applications must be cleared separately.
  • Website cloud favorites: Removing a favorite while signed in uses the API to delete that account’s D1 favorite row. After success, other devices see the change when they reload favorites. Failed requests restore the previous state and show a retry message; offline changes are not queued for background upload.
  • Website local data and sign-out: Clearing data for the relevant website origin removes its preferences, anonymous favorites and backups, import records, and the short-lived site session and login-verification data in sessionStorage. Clearing local data before the first import succeeds loses favorites that have not uploaded. Signing out or clearing local data does not delete successfully saved cloud favorites; signing in again can restore them.
  • Permanent cloud deletion: Contact the maintainer to request removal of the website account, its sessions and all cloud favorites. You can manage GitHub authorization in GitHub application settings; revoking authorization does not itself delete existing site data. Do not post tokens, passwords or favorite lists in public Issues.
  • Retention: Extension favorites and preferences remain until removed or the extension is uninstalled; catalog caches may be replaced. Cloud favorites shared by the website and extension remain until you remove them or the account is deleted. Site sessions last up to eight hours; sign-out revokes the current client’s session. The website tab and extension chrome.storage.session have separate session and account-cache lifetimes and do not provide permanent backups. Backup and infrastructure-log retention depends on project and provider settings; deleting a database record does not mean infrastructure backups are immediately cleared. Search terms are not stored in the cloud favorites database.

Catalog updates use HTTPS. Local storage is protected by your browser and device; the extension does not provide a separate encryption or cloud backup service for its local cache.

Data use commitments

We handle extension data only for the search, filter, favorites, preferences and catalog-update features described here. We do not sell user data or use it for personalized advertising, data brokerage, credit assessments or lending. The extension does not upload browser searches or selected text. Only when you choose sign-in do the extension and website send account identity, favorite repository IDs, and public metadata to the same service for sign-in, favorite synchronization, related operation, and deletion requests.

Agent Leaderboard’s use of information obtained through Chrome extension APIs adheres to the Chrome Web Store User Data Policy, including its Limited Use requirements. The extension does not use Google account sign-in or request access to Google account data.

Policy updates and contact

If features or data practices change, we will update this page and its date, and communicate the changes as required by applicable platform rules.

For privacy questions or behavior that appears inconsistent with this policy, contact the maintainer through GitHub Issues. Issues are public; do not post passwords, credentials or other sensitive information. Feedback you choose to submit is stored by GitHub under its privacy policy and is used by the maintainer to address your feedback.
