Privacy Policy

Effective and last updated: October 31, 2026 · Extension version: 1.6.0

This policy explains how Agent Leaderboard handles data when you use its Chrome search assistant and website.

Extension searches and filters run on your device. Extension favorites stay in your current browser. The extension requires no account. The extension does not upload searches or favorites to the developer, read browsing history, cookies or full webpage content, or include advertising or analytics code. Catalog updates make necessary network requests. Separately, when configured and you choose to sign in, the website offers GitHub sign-in and account-based cloud favorites through Supabase.

Scope

This policy covers the Agent Leaderboard Chrome extension and agentskills.media, maintained by Jiancheng Pan (GitHub: jaychempan). The extension searches, filters and bookmarks public AI tool repositories, and copies repository links and installation prompts.

The extension and website use separate browser storage. Extension favorites do not sync with the website or other devices. When cloud services are configured, signed-in website favorites can sync across devices using the same GitHub account. GitHub repositories, external websites and AI coding services you choose to open are governed by their own privacy policies.

What the extension handles locally

Search terms, filters and text you select
Terms entered in the extension or address bar, and text you actively submit through the selection context menu, are used only to search the local catalog. The extension does not automatically scan webpages. Current searches and filters are kept in browser session storage; context-menu requests are removed after receipt and are not sent to a search server. Address-bar searches and fallback search pages may include terms in a local chrome-extension:// page URL.
Bookmarked repositories
Repository identifiers and public repository details from the time of bookmarking are stored locally to display your favorites. The extension has no favorites account or cloud synchronization; optional website cloud favorites do not read extension storage.
Preferences and catalog cache
Language, theme, the public catalog cache and the last check time are stored locally to restore preferences, support offline searches and control update frequency.
Copied links and installation prompts
Only when you click a copy button does the extension write a repository link or generated installation prompt to your system clipboard. It does not read the clipboard, automatically send content to an AI service, or run installations. If you paste content into another application, that application handles the content you choose to share.

Network requests and third-party services

Public catalog updates

On first opening, when opened more than 24 hours after the last successful check, or when you manually refresh, the extension requests https://agentskills.media/data/discovery_index.json over HTTPS. This request does not include search terms, favorites, selected text or browser cookies. A cached or bundled catalog remains usable offline.

As with other website requests, hosting and network infrastructure serving the website receive connection information such as your IP address, request time, request path and browser request headers. They may retain access logs for service delivery, security or troubleshooting. The website is published through GitHub Pages. Infrastructure providers handle data under their own policies, including the GitHub Privacy Statement. This project does not set or promise a uniform retention period for those infrastructure logs.

Links you choose to open

Opening a repository, README, website or feedback link makes a normal browser request to the destination, which receives request information under its own policies. The extension does not read conversations in ChatGPT, other AI tools or other browser extensions.

Why the extension uses its permissions

storage
Stores the local catalog cache, favorites, language and theme preferences, and temporary search state.
sidePanel
Displays the search assistant in Chrome’s side panel.
contextMenus
Provides a menu to search selected text. Selected text is used only when you actively click that menu item.
https://agentskills.media/*
Allows public catalog updates from the official website. The extension does not request permissions to read browsing history, cookies, arbitrary webpage content or clipboard contents.

Website data

The website stores language, theme, list-view preferences and website favorites in browser localStorage. Search and filtering run in your browser and are not sent to the favorites database. Without sign-in, favorites stay on the current device.

Optional GitHub sign-in and cloud favorites

When Supabase is configured, you can choose to sign in with GitHub. GitHub provides Supabase with identity information such as your GitHub user ID, username, avatar and email information needed for authentication. Supabase handles the account session. The website stores session credentials, account-specific favorite caches and queued changes in browser storage to restore sign-in and support offline use. Existing local favorites are merged on first sign-in; additions and removals after sign-in are synchronized with that account. Website favorites do not automatically change GitHub Stars and do not require reading or changing your repository code.

The configured Supabase project stores cloud favorites, including account and repository identifiers, public repository details used to display favorites, deletion markers and server timestamps. Database access rules restrict ordinary users to their own records. This is not end-to-end encrypted storage: project maintainers can manage cloud records for service operation, troubleshooting and deletion requests. Supabase and GitHub receive connection information needed for sign-in and synchronization, under the Supabase Privacy Policy and the GitHub Privacy Statement linked above. Signing out or clearing local data does not delete successfully synchronized cloud favorites.

The website leaderboard displays daily page views (PV) and total visitors (UV); the extension does not include this counter. Loading the leaderboard at https://agentskills.media or https://jaychempan.github.io/Agent-Leaderboard/ sends one request to the public soxft/busuanzi service at https://busuanzi.9420.ltd/api. Both hosts share one canonical namespace. A virtual path containing the Asia/Shanghai date groups daily page loads; total visitors are deduplicated by the service, not verified real people. Board, filter and language changes do not recount. The service identifies visitors using IP, browser User-Agent and a signed anonymous identity. That identity is stored in localStorage as st_visit_identity_v1 and sent with statistics requests. Clearing storage or switching devices can affect deduplication.

Visit-counter requests contain only the canonical site address, statistics date and anonymous identity, with an origin-only Referer. They do not send searches, query strings, favorites, referring-page URLs or third-party cookies. The service receives normal connection information including IP and browser headers; its open-source implementation hashes statistics identifiers. The public service has no SLA or data-integrity guarantee, and this project does not promise its retention period. History from previous services has not been migrated. Local preview requests only the local /api/visits endpoint, storing daily counts and anonymous browser IDs in its local database. Local IDs are stored as st_local_visit_id, never sent to third parties; the local counter does not record IP addresses. Other preview hosts do not enable statistics.

This privacy page does not load visit counters, external fonts or third-party scripts. Loading the page itself still makes the hosting requests described above. The website’s example installation-prompt button only writes the content you choose to copy; it does not automatically contact AI services.

Retention, controls and deletion

  • Extension favorites: Click a bookmarked repository’s bookmark button again to remove its locally saved favorite record.
  • Temporary searches: Clearing a search or changing filters updates the current session state. Closing one side panel does not necessarily clear session storage. The browser clears extension session storage when the browser restarts or the extension is reloaded, disabled or updated.
  • All extension data: Uninstalling removes favorites, settings and catalog caches from the extension’s browser storage. Browser history, tab URLs, system clipboard contents and content copied into other applications must be cleared separately in those locations.
  • Website cloud favorites: Removing a favorite while signed in synchronizes a deletion marker that other devices use to remove the favorite. The marker retains its repository identifier and timestamp to prevent an older device restoring a removed favorite; this is not permanent physical deletion of the database row. Offline removals affect cloud records after connectivity returns and synchronization succeeds.
  • Website local data and sign-out: Clearing data for the relevant website origin removes that origin's preferences, session, favorite caches and unsynchronized changes. Signing out or clearing local data does not delete synchronized cloud records; signing in again can restore them. Clearing changes before they upload loses those changes.
  • Permanent cloud deletion: Contact the maintainer to request permanent removal of cloud favorites or the website account. Deleting the Supabase user cascades to its favorite rows. You can manage GitHub authorization in GitHub application settings; revoking authorization does not itself delete existing cloud data. Do not post tokens, passwords or favorite lists in public Issues.
  • Retention: Extension favorites and preferences remain until removed or the extension is uninstalled; catalog caches may be replaced. Synchronized website favorites and deletion markers remain until the relevant cloud data or account is permanently deleted. Backup and infrastructure-log retention depends on project and provider settings. Search terms are not stored in the cloud favorites database.

Catalog updates use HTTPS. Local storage is protected by your browser and device; the extension does not provide a separate encryption or cloud backup service for its local cache.

Data use commitments

We handle extension data only for the search, filter, favorites, preferences and catalog-update features described here. We do not sell user data or use it for personalized advertising, data brokerage, credit assessments or lending. The extension does not upload browser searches or favorites. Optional website identity information and cloud favorites are used for sign-in, favorite synchronization, related service operation and deletion requests.

Agent Leaderboard’s use of information obtained through Chrome extension APIs adheres to the Chrome Web Store User Data Policy, including its Limited Use requirements. The extension does not use Google account sign-in or request access to Google account data.

Policy updates and contact

If features or data practices change, we will update this page and its date, and communicate the changes as required by applicable platform rules.

For privacy questions or behavior that appears inconsistent with this policy, contact the maintainer through GitHub Issues. Issues are public; do not post passwords, credentials or other sensitive information. Feedback you choose to submit is stored by GitHub under its privacy policy and is used by the maintainer to address your feedback.
